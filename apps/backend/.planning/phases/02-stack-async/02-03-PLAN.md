## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator → migrations | `alembic upgrade head` aplica DDL — operação privilegiada; deve usar credenciais do banco corretas |
| settings.DATABASE_URL → engine de migration | URL pode conter senha; é injetada via `configuration["sqlalchemy.url"]` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-04 | Information Disclosure | `configuration["sqlalchemy.url"] = settings.DATABASE_URL` | accept | `alembic` não loga `sqlalchemy.url` por padrão; logging.config é controlado pelo fileConfig do alembic.ini (que não habilita echo). Senha não vaza no path normal. |
| T-2-05 | Denial of Service | `await connectable.dispose()` | mitigate | Sem `dispose()`, asyncpg deixa conexões abertas no servidor PostgreSQL e o processo do alembic pode dar hang — Pitfall 5 documentado. Mitigado por chamada explícita após cada run. |
| T-2-06 | Tampering | DDL gerado em autogenerate via `from caramello.models import *` | accept | Migrations são revisadas por humano antes de `upgrade head`. Sem auto-merge de migrations geradas. |
</threat_model>

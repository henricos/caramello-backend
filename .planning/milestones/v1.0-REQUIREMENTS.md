### Modelo de Dados

- [x] **MODEL-01**: Tabela `users` apenas com campos Keycloak (idp_sub, email, name) _(Phase 1)_
- [x] **MODEL-02**: Migration `0001_initial_schema.py` — schema final consolidado, limpo _(Phase 1 + M1 close)_
- [x] **MODEL-03**: DB naming `caramello_dev`/`caramello` — .env.example atualizado _(Phase 5-06)_

- [x] **AUTH-01**: Endpoints protegidos retornam 401 sem Bearer token válido _(Phase 3)_
- [x] **AUTH-02**: JIT provisioning via `ON CONFLICT DO NOTHING` na primeira request _(Phase 3)_
- [x] **AUTH-03**: `shared/auth.py` isola validação JWT — JWKS cacheado _(Phase 3)_

### Estrutura por Domínios

- [x] **STRUCT-01**: Código em `src/caramello/users/`, `src/caramello/families/`, `src/caramello/shared/` _(Phase 3)_
- [x] **STRUCT-02**: DSL generator com campo `domain` produz código no diretório correto _(Phase 3)_

### Domínio User

- [x] **USER-01**: `GET /users/me` retorna perfil do usuário autenticado _(Phase 3)_

### Domínio Family

- [x] **FAMILY-01**: `POST /families/registry` cria família e torna usuário owner _(Phase 4)_
- [x] **FAMILY-02**: `GET /families/families` lista famílias do usuário _(Phase 4)_
- [x] **FAMILY-03**: `GET /families/families/{uuid}` retorna detalhes se membro, 403 senão _(Phase 4)_
- [~] **FAMILY-04**: Código de convite reutilizável — **DEFERIDO M2** (D-04)
- [~] **FAMILY-05**: Solicitação de entrada via convite — **DEFERIDO M2** (D-04)
- [~] **FAMILY-06**: Aprovação/rejeição de solicitações — **DEFERIDO M2** (D-04)
- [x] **FAMILY-07**: `DELETE /families/families/{uuid}/members/{user_uuid}` e `GET /members` _(Phase 4)_

> FAMILY-04/05/06 substituídos pelo fluxo de pré-registro por email (D-01/D-02), adequado ao grupo familiar fechado de 1-5 usuários.

### MCP — Model Context Protocol

- [x] **MCP-01**: Cliente MCP em `/mcp` descobre `list_my_families` _(Phase 5)_
- [x] **MCP-02**: Ferramentas MCP exigem Bearer token — mesmo mecanismo dos endpoints REST _(Phase 5)_

### Deploy e Containerização

- [x] **DEPLOY-01**: Dockerfile multi-stage, non-root user, sem secrets no layer de build _(Phase 5)_
- [x] **DEPLOY-02**: `docker compose up` com configuração exclusivamente via env vars _(Phase 5)_
- [x] **DEPLOY-03**: `APP_VERSION` como build arg exposto na OpenAPI spec _(Phase 5)_

### Testes

- [x] **TEST-01**: Testes rodam contra `caramello_dev` com rollback por savepoint por teste _(Phase 5)_
- [x] **TEST-02**: 4 testes de integração do domínio family (criar, listar, pré-registrar, listar membros) _(Phase 5)_
- [x] **TEST-03**: `dependency_overrides` simulam usuário autenticado sem Keycloak real _(Phase 5)_

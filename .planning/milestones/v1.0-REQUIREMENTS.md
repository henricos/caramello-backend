## v1 Requirements — Final Status

### Async Infrastructure

- [x] **INFRA-01**: Complete async stack — asyncpg, AsyncSession, async Alembic _(Phase 2)_
- [x] **INFRA-02**: `ruff` and `mypy` pass with no errors across 16 files _(Phase 1)_
- [x] **INFRA-03**: CORSMiddleware configured with CORS_ORIGINS via settings _(Phase 1)_

### Data Model

- [x] **MODEL-01**: `users` table with Keycloak fields only (idp_sub, email, name) _(Phase 1)_
- [x] **MODEL-02**: Migration `0001_initial_schema.py` — final consolidated schema, clean _(Phase 1 + M1 close)_
- [x] **MODEL-03**: DB naming `caramello_dev`/`caramello` — .env.example updated _(Phase 5-06)_

### Authentication and Authorization

- [x] **AUTH-01**: Protected endpoints return 401 without a valid Bearer token _(Phase 3)_
- [x] **AUTH-02**: JIT provisioning via `ON CONFLICT DO NOTHING` on the first request _(Phase 3)_
- [x] **AUTH-03**: `shared/auth.py` isolates JWT validation — cached JWKS _(Phase 3)_

### Domain-Based Structure

- [x] **STRUCT-01**: Code in `src/caramello/users/`, `src/caramello/families/`, `src/caramello/shared/` _(Phase 3)_
- [x] **STRUCT-02**: DSL generator with a `domain` field produces code in the correct directory _(Phase 3)_

### User Domain

- [x] **USER-01**: `GET /users/me` returns the authenticated user's profile _(Phase 3)_

### Family Domain

- [x] **FAMILY-01**: `POST /families/registry` creates a family and makes the user owner _(Phase 4)_
- [x] **FAMILY-02**: `GET /families/families` lists the user's families _(Phase 4)_
- [x] **FAMILY-03**: `GET /families/families/{uuid}` returns details if a member, 403 otherwise _(Phase 4)_
- [~] **FAMILY-04**: Reusable invitation code — **DEFERRED M2** (D-04)
- [~] **FAMILY-05**: Join request via invitation — **DEFERRED M2** (D-04)
- [~] **FAMILY-06**: Approval/rejection of requests — **DEFERRED M2** (D-04)
- [x] **FAMILY-07**: `DELETE /families/families/{uuid}/members/{user_uuid}` and `GET /members` _(Phase 4)_

> FAMILY-04/05/06 replaced by the e-mail pre-registration flow (D-01/D-02), suited to the closed family group of 1-5 users.

### MCP — Model Context Protocol

- [x] **MCP-01**: MCP client at `/mcp` discovers `list_my_families` _(Phase 5)_
- [x] **MCP-02**: MCP tools require a Bearer token — the same mechanism as the REST endpoints _(Phase 5)_

### Deploy and Containerization

- [x] **DEPLOY-01**: Multi-stage Dockerfile, non-root user, no secrets in the build layer _(Phase 5)_
- [x] **DEPLOY-02**: `docker compose up` with configuration exclusively via env vars _(Phase 5)_
- [x] **DEPLOY-03**: `APP_VERSION` as a build arg exposed in the OpenAPI spec _(Phase 5)_

### Tests

- [x] **TEST-01**: Tests run against `caramello_dev` with a per-test savepoint rollback _(Phase 5)_
- [x] **TEST-02**: 4 integration tests for the family domain (create, list, pre-register, list members) _(Phase 5)_
- [x] **TEST-03**: `dependency_overrides` simulate an authenticated user without a real Keycloak _(Phase 5)_

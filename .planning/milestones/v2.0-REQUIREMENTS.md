## Domain Glossary

| Term | Concept |
|-------|---------|
| **Account** | Bank account, card, savings or investment account belonging to a family member |
| **Movement** | Raw bank fact — credit or debit with date, amount and description; immutable |
| **Financial entry** | Movement reconciled with meaning: category (2 levels) + competência (year/month) + analytical fields; the basis of every report |
| **Category** | 2-level hierarchy (Transporte > Gasolina) scoped by family |
| **Competência** | Accounting period (year/month) of the financial entry; may differ from the movement date |
| **Reconciliation** | The act of turning a raw movement into a classified financial entry |

## Requirements — Final Status

### Accounts

- [x] **ACC-01**: Authenticated user can create an account for their family (name, type, currency) — `POST /finances/accounts`
- [x] **ACC-02**: User can list, detail and update the family's accounts — `GET/PATCH /finances/accounts`
- [x] **ACC-03**: User can archive an account (`is_active=false`) without losing history — `PATCH` with `is_active=false`

### Categories

- [x] **CAT-01**: User can create a level 1 (parent) category for the family — `POST /finances/categories`
- [x] **CAT-02**: User can create a level 2 subcategory linked to a parent category — `POST /finances/subcategory`
- [x] **CAT-03**: System rejects creating a subcategory as a child of a subcategory — structurally enforced by the 2-table schema
- [x] **CAT-04**: User can list and update the family's categories — `GET/PATCH /finances/categories`

### Movements

- [x] **MOV-01**: User can record an individual movement — `POST /finances/accounts/{uuid}/movements` _(checkbox not updated in the original REQUIREMENTS.md — implemented in Phase 8)_
- [x] **MOV-02**: User can import movements via CSV — `POST /finances/accounts/{uuid}/movements/import`
- [x] **MOV-03**: User can import via OFX or XLSX — same endpoint, ofxparse/openpyxl parsers
- [x] **MOV-04**: Import detects duplicates via SHA-256 hash — `import_hash UNIQUE` + `on_conflict_do_nothing`
- [x] **MOV-05**: Duplicates flagged `is_duplicate=true` instead of rejected

### Financial Entries (Reconciliation)

- [x] **LAN-01**: User can reconcile a movement by creating a financial entry — `POST /finances/movements/{uuid}/reconcile`
- [x] **LAN-02**: A movement has at most one entry (1:1) — 409 on the second attempt
- [x] **LAN-03**: System proposes a subcategory by similarity — `GET /finances/movements/{uuid}/suggest-category` via rapidfuzz
- [x] **LAN-04**: User can mark an entry as recurring — `is_recorrente` field on FinancialEntry
- [x] **LAN-05**: User can update an entry's subcategory and competência — `PATCH /finances/entries/{uuid}`

### Reports and Balances

- [x] **REL-01**: Current balance of an account — `GET /finances/accounts/{uuid}/balance`
- [x] **REL-02**: Consolidated balance of all the family's accounts — `GET /finances/families/{uuid}/balance`
- [x] **REL-03**: Monthly breakdown by parent category — `GET /finances/reports/monthly`
- [x] **REL-04**: Detail by subcategory within a parent category and competência — filter on `monthly`
- [x] **REL-05**: Analytical reports operate on financial entries by competência — confirmed

### Authorization

- [x] **AUTH-FIN-01**: Every finance endpoint requires a Bearer token — `Depends(get_current_user)` on all routes
- [x] **AUTH-FIN-02**: User only accesses data of families they are a member of — `_require_family_access()` helper

## Out of Scope for M2 (confirmed)

| Feature | Reason | Destination |
|---------|-------|---------|
| Automatic generation of recurrences | It is only flagged as recurring; auto-generation comes in M3 | M3 |
| Granular per-member permissions | M2 focuses on the owner | M3 |
| Automatic statement cycles per account | Unnecessary complexity | Backlog |
| Movement splits (1:N) | 1:1 reconciliation is sufficient | Backlog |
| Budget/forecast/goals | Separate domain | Future |
| Open Banking / automatic feeds | Unnecessary scale for 1-5 users | Future |
| FAMILY-04/05/06 (reusable invitations) | Deferred from M1 | M3 |
| Financial MCP (D-MCP-01) | The APIs must mature first | M3 |

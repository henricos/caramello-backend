## Glossário do Domínio

| Termo | Conceito |
|-------|---------|
| **Conta** | Conta bancária, cartão, poupança ou investimento de um membro da família |
| **Movimentação** | Fato bancário bruto — crédito ou débito com data, valor e descrição; imutável |
| **Lançamento financeiro** | Movimentação conciliada com significado: categoria (2 níveis) + competência (ano/mês) + campos analíticos; base de todos os relatórios |
| **Categoria** | Hierarquia 2 níveis (Transporte > Gasolina) scoped por família |
| **Competência** | Período contábil (ano/mês) do lançamento financeiro, pode diferir da data da movimentação |
| **Conciliação** | Ato de transformar uma movimentação bruta em um lançamento financeiro classificado |

## Requisitos — Status Final

### Contas

- [x] **ACC-01**: Usuário autenticado pode criar conta para sua família (nome, tipo, moeda) — `POST /finances/accounts`
- [x] **ACC-02**: Usuário pode listar, detalhar e atualizar contas da família — `GET/PATCH /finances/accounts`
- [x] **ACC-03**: Usuário pode arquivar conta (`is_active=false`) sem perder histórico — `PATCH` com `is_active=false`

### Categorias

- [x] **CAT-01**: Usuário pode criar categoria de nível 1 (pai) para a família — `POST /finances/categories`
- [x] **CAT-02**: Usuário pode criar subcategoria de nível 2 vinculada a categoria pai — `POST /finances/subcategory`
- [x] **CAT-03**: Sistema rejeita criação de subcategoria filha de subcategoria — enforced estruturalmente por schema de 2 tabelas
- [x] **CAT-04**: Usuário pode listar e atualizar categorias da família — `GET/PATCH /finances/categories`

### Movimentações

- [x] **MOV-01**: Usuário pode registrar movimentação individual — `POST /finances/accounts/{uuid}/movements` _(checkbox não atualizado no REQUIREMENTS.md original — implementado na Phase 8)_
- [x] **MOV-02**: Usuário pode importar movimentações via CSV — `POST /finances/accounts/{uuid}/movements/import`
- [x] **MOV-03**: Usuário pode importar via OFX ou XLSX — mesmo endpoint, parsers ofxparse/openpyxl
- [x] **MOV-04**: Importação detecta duplicatas via SHA-256 hash — `import_hash UNIQUE` + `on_conflict_do_nothing`
- [x] **MOV-05**: Duplicatas marcadas `is_duplicate=true` em vez de rejeitadas

### Lançamentos Financeiros (Conciliação)

- [x] **LAN-01**: Usuário pode conciliar movimentação criando lançamento financeiro — `POST /finances/movements/{uuid}/reconcile`
- [x] **LAN-02**: Uma movimentação tem no máximo um lançamento (1:1) — 409 na segunda tentativa
- [x] **LAN-03**: Sistema propõe subcategoria por similaridade — `GET /finances/movements/{uuid}/suggest-category` via rapidfuzz
- [x] **LAN-04**: Usuário pode marcar lançamento como recorrente — campo `is_recorrente` em FinancialEntry
- [x] **LAN-05**: Usuário pode atualizar subcategoria e competência de lançamento — `PATCH /finances/entries/{uuid}`

### Relatórios e Saldos

- [x] **REL-01**: Saldo atual de uma conta — `GET /finances/accounts/{uuid}/balance`
- [x] **REL-02**: Saldo consolidado de todas as contas da família — `GET /finances/families/{uuid}/balance`
- [x] **REL-03**: Breakdown mensal por categoria pai — `GET /finances/reports/monthly`
- [x] **REL-04**: Detalhe por subcategoria dentro de categoria pai e competência — filtro em `monthly`
- [x] **REL-05**: Relatórios analíticos operam sobre lançamentos financeiros por competência — confirmado

### Autorização

- [x] **AUTH-FIN-01**: Todos os endpoints finance exigem Bearer token — `Depends(get_current_user)` em todas as rotas
- [x] **AUTH-FIN-02**: Usuário só acessa dados de famílias das quais é membro — `_require_family_access()` helper

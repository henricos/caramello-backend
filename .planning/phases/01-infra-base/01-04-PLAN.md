**Passo 1 — Deletar a migration antiga:**

```bash
rm alembic/versions/20260104-1044-e667565d64eb-fix_relationships.py
```

**Passo 2 — Garantir banco vazio:**

A migration será gerada com `--autogenerate`, que compara os modelos com o banco atual. Para um resultado limpo, o banco `familia_dev` deve estar vazio (sem tabelas do Alembic). Se o banco tiver estado anterior:

```bash
# Verificar estado do banco (requer banco acessível)
uv run alembic current 2>&1
```

Se retornar erro de conexão (banco indisponível), seguir para o Passo 3 mesmo assim — o `--autogenerate` lê apenas os modelos Python, não precisa do banco para gerar o arquivo de migration. O banco é necessário apenas para `alembic upgrade head`.

**Passo 3 — Gerar nova migration com nome descritivo:**

```bash
uv run alembic revision --autogenerate -m "initial_schema"
```

Este comando gera um arquivo em `alembic/versions/` com timestamp + `initial_schema` no nome. O arquivo gerado deve conter operações `op.create_table` para as 4 tabelas.

**Passo 4 — Inspecionar o arquivo gerado:**

Abrir o arquivo gerado e verificar:
- Função `upgrade()` contém `op.create_table("user", ...)` com coluna `idp_sub`
- Função `upgrade()` NÃO contém `hashed_password`, `google_id`, `phone_number`, `is_active`
- Função `downgrade()` contém `op.drop_table` para as 4 tabelas

Se o arquivo gerado não contiver `idp_sub` ou contiver campos errados, significa que os modelos Python em `src/caramello/models/user.py` não foram regenerados corretamente no Plano 01-01. Nesse caso, parar e reportar o problema — não corrigir a migration manualmente.

**Atenção:** O nome do arquivo gerado terá um prefixo de timestamp (ex: `20260524_1234_initial_schema.py`). Isso é correto — não renomear.

<threat_model>
## Limites de Confiança

| Limite | Descrição |
|--------|-----------|
| Migration → banco de dados | DDL irreversível se `downgrade()` não for testado |
| Modelos Python → migration gerada | Autogenerate pode omitir constraints se o modelo não as declarar |

## Registro de Ameaças STRIDE

| ID | Categoria | Componente | Disposição | Plano de Mitigação |
|----|-----------|------------|------------|-------------------|
| T-04-01 | Tampering | alembic/versions/ | aceitar | Diretório versionado em git; deletar a migration antiga é intencional e rastreável |
| T-04-02 | Denial of Service | Migration incorreta aplicada | mitigar | Checkpoint humano verifica colunas antes de continuar — não avançar para Phase 2 com schema errado |
| T-04-03 | Information Disclosure | `idp_sub` sem índice único | mitigar | Campo declarado como `unique: true` no YAML — autogenerate deve emitir `UniqueConstraint`; inspecionar migration gerada no Task 1 |
